# learned-rules

> 反复踩过的坑 → 固化成规则。来源为历史挖掘（已脱敏）。≤30 条，发现新坑追加，过时删。
> 格式：**场景** — 踩坑 → **规则**（来源）

## 技术机制
1. **本地推理对话格式** — `llm.generate` 走 `create_completion`（文本补全）不套对话模板；Qwen2.5 训练用 ChatML，裸文本/Vicuna 格式下模型不识别 assistant 回合边界、不生成 `<|im_end|>`，stop 不触发 → 生成跑到 `max_tokens`。→ **对话格式与 stop 统一在 LocalLLM 封装层按 ChatML 处理，`stop=["<|im_end|>"]`**。（lesson1-2 归因）
2. **格式/结束符归属** — 一度误以为对话格式/结束符由 SDK 端处理，实为：本地 llama-cpp 进程内**自己拼模板**，服务端 API 才由服务端套。→ **分清"谁拼模板"，本地必须显式拼 ChatML**。（02 文档勘误）
3. **模型文件名混淆** — `llama-3-8b-instruct.gguf` 实为 Qwen2.5-7B-abliterated，是"昨天 qwen 今天 llama"困惑的源头。→ **模型正名 `qwen2.5-7b-instruct-abliterated.gguf` + 路径收敛 `shared/config.py`，禁止硬编码**。
4. **工具调用** — 反复出现 `Your tool call was malformed and could not be parsed`。→ **工具调用 schema 严格对齐，malformed 时重试**。（lesson5）
5. **注释三处同步** — 代码注释里的 `CRITICAL INSTRUCTIONS` 需与 prompt 文本多处同步对齐。→ **改 prompt 同时改全部对照副本，勿漏**。

## 工程纪律
6. **断言** — 未先看实际返回 `res` 内容就写断言 → 被质问。→ **写断言前先打印/看真实返回（TDD：先复现再断言）**。
7. **过度设计** — demo/封装过度被明确斥责。→ **最小可运行优先，不过度封装/设计**。
8. **改文件范围** — 擅自改未授权文件 / 改他人分享稿 → 被要求 git 回退。→ **只动 user 指定文件，不碰他人 git 变更；commit/push 仅 user 要求时**。

## 沟通 & 文档
9. **不替学习** — 绕过 user 学习、不解释底层、瞎猜不联网 → 强烈不满。→ **讲底层机制、不藏推理；技术结论联网核实给信源，不臆断**。
10. **i18n 标点** — 中文化时标点不彻底（逗号/分号没换全角）→ 激烈不满。→ **i18n 标点彻底替换，连同正文一起核**。
11. **文档风格** — 比喻/修饰/"当前进度·下一步"类话术被反对。→ **干净最简技术语言，禁比喻修辞**。
12. **笔记取舍** — 不记录琐碎翻译问题（如某词为何不中文化）。→ **答疑笔记只沉淀有学习价值的点**。
